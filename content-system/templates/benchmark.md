# Evaluate a specific claim

## Question and claim boundary

State the hypothesis and workload. Mark results pending until measurements exist. Name sponsorship/author and avoid universal superiority claims.

## Reproduction manifest

Record dataset/license/split, query labels, product and SDK versions, model/judge versions, hardware/cloud/region, replicas, index settings, dimensions/distance, quantization, concurrency, cache state, warmup and repeated runs. Link code revision and raw results.

## Baselines and fairness

Explain equal information access, quality targets, tuning budget and held-out queries. Disclose differences that cannot be controlled.

## Method and metrics

Separate retrieval quality from answer quality. Include latency distributions, failures and total billed work. Memory comparisons should include ingestion/extraction, embedding, recall, generation and infrastructure; token reduction alone is not total savings.

## Results

| Configuration | Quality | Latency | Total cost | Failure cases |
|---|---|---|---|---|
| Pending measurement | Not measured | Not measured | Not measured | Not measured |

## Wins, losses and sensitivity

Show trade-offs and variance. Include stale/changed information, strict filters or isolation cases as appropriate. Do not hide unsuccessful configurations.

## Reproduce and clean up

Provide exact commands, expected artifacts, cost controls and teardown. Never run unbounded paid tests by default.

## Limitations and conclusion

State what the data does and does not establish, and one next experiment.

## Sources

Link primary documentation, dataset and comparison methodology.
