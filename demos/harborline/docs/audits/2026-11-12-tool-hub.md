# Hotel Tool Hub

The `/hub` page opens from the concierge’s Tool Hub button in a separate browser tab.

- Catalog lists 12 functions and seven policies. Live records are read by allowlisted name from Agent Catalog; metadata includes the stored version timestamp, identifier, bucket, scope and collection.
- JSON is a public SDK projection. Raw source, embeddings and credential fields are omitted. Simulation uses bundled contracts and does not invent published metadata.
- Trace history combines the current visitor’s concierge history and isolated Tool Hub history. Stored trace JSON is available only for record IDs referenced by that visitor’s saved history, with a second session check against the stored span.
- Live Run function loads the published callable through Agent Catalog. No model calls are used. A separate `::tool-hub` session and lease isolate sandbox state from concierge bookings. A shared 120-call/day tool-run guard applies.
- Sample-stay reset is explicit. Function prerequisites remain enforced. Booking and cancellation actions stop for approval. Simulation is an illustrative browser implementation, not execution in Capella.

Verified: all 19 live records loaded; membership, reservation lookup and upgrade executed in order; returned upgrade was saved; all six tool events had verified Agent Tracer records; three runner history entries persisted; concierge bookings remained empty. Backend suite: 30 tests passed.

No changes to managed memory or infrastructure provisioning.
